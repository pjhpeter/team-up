# 真实浏览器验收

用真实浏览器（或 Electron 桌面窗口）、真实后端，按用户能做的操作逐条走验收点，优先保存本轮实际操作的过程录屏（无法录屏或静态细节看不清时用截图补足）并给出结论；测完把自己启动的服务、浏览器会话和桌面客户端关干净。看起来对、单元测试过了、jsdom 跑通了，都不能代替这一步。

先确定这一轮是哪种：

- **本地验收**（需要本地独立服务的正常流程）：在本 issue 的 worktree 新启动专属服务来测。
- **部署后验收**（单分支低风险直达合并冒烟、测试环境冒烟、debug 模式）：直接测已部署的测试环境地址，**不启动**本地 Web 服务或开发版 Electron，也不关闭远端服务。涉及主进程、preload、安装更新等桌面原生能力时，用包含本次改动、连接测试环境的测试客户端，记录测试包版本、构建 SHA、来源和连接环境。网页通过不能代替桌面原生验收。

## 步骤

### 1. 读已有经验与固定证据目录

- 开测前读本任务的 `<任务目录>/test/howto.md`（登录、入口、造数、坑），以及项目的 `<主仓库>/.hwf/test-data.md`（可复用测试数据；主仓库是 `git rev-parse --git-common-dir` 的上一级）。文件不存在就在收尾时新建。
- **证据目录固定前缀**：本轮全部本地录屏、截图、报告、终端日志及临时 `browser-profile`，在团队流程中一律写入 `<主仓库>/.hwf/tmp/<任务标识>/testing/<轮次>/`（绝对路径）；非团队单次测试写 `<仓库根目录>/.tmp/testing/<轮次>/`。派活若写了相对路径（如 `testing/xxx`），必须解析到 `<主仓库>/.hwf/tmp/<任务标识>/testing/xxx`，**严禁**在仓库根目录或 worktree 根目录直接新建 `testing/`、`evidence/`、`test/` 等顶层目录，也严禁修改仓库 `.gitignore` 遮盖放错位置的测试产物。

### 2. 启动专属服务（仅本地验收）

- 以本 issue 的 worktree 为 cwd 新启动服务，不复用本 worktree 先前 issue、其他成员、用户或任何已在运行的服务。
- 先查端口归属，被别人占用就按仓库规则另选空闲端口（若仓库开发版 Electron 或本地网关要求固定端口如 `3001`，核实该端口空闲后直接启动，被他人占用时才报阻塞，不复用、不停止对方服务）。记录端口、origin、进程标识、启动时间。无法保证 origin 隔离就报阻塞。
- 确需在别处启动，记录 PID，收尾按 PID 关闭。
- 只有涉及主进程、preload、安装更新、其他原生能力或需求明确要求时才启动 Electron；需要本地 Electron 验收时直接在本 issue worktree 运行仓库开发版 Electron 启动命令并用 `Computer Use` 操作该独立窗口，除非需求本身验收安装包/自动更新，否则不索要签名安装包，也不为启动本地服务请示用户。网页和 Electron 都涉及时分别覆盖、分别列结果。

部署后验收改为：核对测试环境实际部署的版本包含本次代码（MR、源 SHA、部署 SHA、成功的部署作业）；前后端都改时分别核对。只凭「已合并」不能开测。

### 3. 预检（不超过 10 分钟）

报告开头逐项写结论和耗时：

1. 被测版本与派活一致：本地验收核对 HEAD 和专属服务；部署后验收核对部署或客户端版本。读取 `docs/agents/herdr-project.yaml` 的 `smoke`：默认只测 `default` 不为 `false` 的站点（如国内测试站）；`default: false` 的站点（如国际/海外站）仅在用户明确要求或本次改动专门涉及该站点独有配置/分支逻辑时才测，未触发时**不检查该站点账号席位、不因缺该站点账号报阻塞**，报告注明「<名称>未验（默认不验）」。
2. 按当前全局「浏览器与 Electron 测试铁律」（`~/.agents/rules/topics/04-tool-usage.md`）按被测对象（网页浏览器或 Electron 桌面窗口）选择对应工具。使用本轮独立的测试环境与分配的账号打开被测页面或独立客户端窗口，确认能实际操作，且能通过 `~/.hwf/scripts/test-record.py` 录制过程视频并解码回放。
3. 页面正常渲染；账号能登录，权限和积分够；真实用户操作能走到功能入口；依赖接口已部署，没有未部署或鉴权错误。
4. 逐条列出每个验收点需要的前置状态和造法。

**自己解决的问题**：浏览器目录、登录、遮罩和弹窗、端口占用、找页面入口、造测试数据。先查 howto 里的已知做法，再换办法；同一问题最多换 2 种办法，仍失败才标阻塞，并报告每种办法和现场。

- **本机测试账号自动登录**：按派活分配的测试账号，从项目约定的本机测试账号凭据文件（如 `~/.agents/secrets/` 下的测试账号清单或 `howto.md` 指明的位置）读取对应密码或测试邮箱验证码，自行输入完成登录（网页表单用 `ego-browser`，Electron 独立客户端窗口用 `Computer Use`）。录屏在登录进入目标界面后再开启（验收登录页本身时只录登录窗口，绝不打开或录制凭据文件，报告和日志不打印明文密码）。测试专用账号在自动化验收中输入密码属于正常自理操作：**严禁**未经自动登录尝试就直接停在登录页叫用户手动登录，也**严禁**在测试后以“自动化输入过密码”为由要求用户轮换测试账号密码；仅当无可用测试账号、触发无法自助收码的真人专属验证/硬件鉴权，或自动登录排障后仍失败时，才报「登录窗口已就绪」交用户接手。
- **Ego Lite 测试站点单站切换账号**：在默认浏览器资料新建本轮 `TaskSpace` 打开非生产测试站点（本地专属端口或 `smoke` 测试域名，如 `develop.bootingai.net`、`app.develop.lookai.app`）时，若自动带入非本轮分配账号的登录态，不向用户索要空白浏览器资料或 `profileId`，按两步自行切换：
  1. **核对同站点并发**：本地专属端口按 `origin` 天然隔离可直接切换；共享测试域名先查 `listTaskSpaces()` 中其他活跃空间的标签页 URL（团队任务同时查 `python3 ~/.hwf/scripts/test-account.py list` 是否有其他在途任务正持有同站点账号），确认没有其他任务正在使用同一测试域名。若同一测试域名正被其他在途任务使用，报并发占用等待，不清对方会话。
  2. **仅清当前测试站点登录态**：在该测试页执行 `localStorage.clear(); sessionStorage.clear()`，调用 `Storage.clearDataForOrigin`（`origin` 仅传当前测试站，`storageTypes: "cookies,local_storage"`），并用 `Network.getAllCookies` 过滤出 `domain`（去前导点后）等于当前测试站 hostname 或其专属测试子域（如 `develop.bootingai.net`、`app.develop.lookai.app`、`develop.lookai.app`）的 Cookie 逐条 `Network.deleteCookies`，刷新后登录本轮账号。**严禁**调用 `Network.clearBrowserCookies`、`Network.clearBrowserCache` 或无 `browserContextId` 的 `Storage.clearCookies`，严禁删除一级根域、生产域名（如 `look-ai.cn`、`lookfashion.ai`）或其他子域（如 `git.bootingai.net`、`admin.lookai.cc`）的 Cookie。

**直接停下回报的问题**：代码缺陷；账号、积分、权限不足；后端未部署或接口报未部署；测试工具本身不可用。

预检第 1–3 项处理后仍不成立，或所有验收点都造不出条件：不跑验收点，按第 6 步清理，以「阻塞」结尾，附对应预检项、报错原文、现场录屏或截图、已试过的办法。只有部分验收点造不出条件，就逐点标阻塞，其余继续；正式测试中某点造条件连续失败 2 次，同样跳到下一点。预检失败不等于免测，真实运行取证门禁仍未满足。

### 4. 逐点验收与过程录屏

- 按已评审的用例（无用例 snippet 的 debug/极简模式按 issue 或 §0 验收点）执行，不按实现结果临时降低通过标准。
- 用真实用户导航到达功能，真实请求连接真实后端，不用模拟接口；后端改动按接口验收，存在页面操作链路时一并覆盖。遵守仓库 `AGENTS.md` 的环境、端口、登录、取证要求，不抢同一个登录会话。
- **优先保存本轮操作过程录屏（`.mp4`）**：按连贯操作流组织成 1～3 段录屏（单段控制在 3 分钟、20 MB 以内），从关键操作前开始录，录到结果出现，失败或受阻也保留现场。统一使用 `~/.hwf/scripts/test-record.py`，禁止手写裸 `.mov` 录屏脚本，只录本轮被测页面或独立客户端窗口，不录桌面、其他窗口或输入密码/令牌的过程：
  - **网页（`ego-browser`）**：
    ```bash
    python3 ~/.hwf/scripts/test-record.py start --mode ego --space-id <spaceId> --out <证据目录>/<场景>.mp4
    # 照常执行 ego-browser nodejs 页面操作与断言（走官方截图采样，不使 @ref 引用失效；handOff 人工接管期间自动暂停抓帧）
    python3 ~/.hwf/scripts/test-record.py stop --out <证据目录>/<场景>.mp4
    ```
  - **Electron 桌面窗口**：在完成登录进入被测界面后开录（除非验收点本身测未登录界面）：
    ```bash
    python3 ~/.hwf/scripts/test-record.py windows --pid <客户端或启动进程PID>
    python3 ~/.hwf/scripts/test-record.py start --mode window --pid <PID> [--window-id <WID>] --out <证据目录>/<场景>.mp4
    # 照常用 Computer Use 操作该独立客户端窗口完成验收
    python3 ~/.hwf/scripts/test-record.py stop --out <证据目录>/<场景>.mp4
    ```
  `stop` 自动校验视频可解码回放、时长与尺寸；记录每个验证点在对应录屏中的起止时间段（如 `00:04–00:18`）和「通过 / 失败 / 阻塞」结论。
- **截图补足边界**：录屏已清楚覆盖的验证点无需重复逐点截图；仅当无法录屏、录屏不可回放、小字号文案或像素间距在视频中看不清（须说明原因），或任务明确要求截图时，用同轮关键步骤与结果的截图补足。
- **按改动大小定走查深度**：
  - **纯局部显隐、文案或单行样式微调**（未改动滚动容器、响应式断点规则、接口契约或按钮确认链路）：在默认桌面视口（≥1200px）打开真实目标页面/弹窗，确认目标内容已按要求显示或隐藏、无异常空行/错位、相邻操作按钮正常展示即可（通常 1 段短录屏，静态文案细节可附 1 张截图）；**不额外注入大批量虚构数据（如 20 条假列表）跑多视口滚动矩阵，也不逐个重测未改动的确认弹窗或退出链路**。
  - **新增页面/弹窗、修改滚动容器或响应式布局、改动交互请求链路**：有设计稿核对颜色、字体、字号、间距、圆角、层级、文案（宽高依内容和容器判断，不照抄固定数值）；无设计稿核对对齐、间距、换行、溢出，无重叠、错位、截断、异常空白，并按受影响范围验证对应视口、滚动与操作链路。偏差退回开发修复后复测。

### 5. 上传录屏与证据链接

用统一媒体上传脚本把本轮交付的 `.mp4` 录屏（及必要的补充截图）上传为 GitLab 项目附件，脚本自动回读核验 SHA-256（拒绝裸 `.mov`）：

```bash
python3 ~/.hwf/scripts/upload-media.py create --repo <主仓库路径> --file <证据目录>/<文件>.mp4 --alt "<场景说明>"
```

- **Herdr 团队任务**：`test` 只调用 `upload-media.py create` 静默上传附件换取链接，**不在 GitLab issue/MR 发评论或改状态**；在测试报告中逐条写明验证点、「通过 / 失败 / 阻塞」结论、所属录屏的 `markdown`（`![说明](/uploads/...)`，供评论内嵌播放器）与 `web_url`（完整直链）及对应时间段（如 `00:04–00:18`），由调度者核验后统一发布。
- **单次非团队任务**：直接对外回报时，附上可访问的录屏链接（GitLab 评论同时内嵌 `markdown` 播放器与 `web_url`），标注环境、SHA、各验证点时间段与结论，回读确认链接可访问。
- 保留旧轮次的失败录屏/截图和记录，不覆盖、不改绿；本地路径或只附本地报告不算交付，无访问或上传能力即报阻塞。

### 6. 每轮清理（回报前必做）

1. 关闭本轮启动的服务和全部后台进程，退出码 0 才算完成，输出原文贴进报告：

   ```bash
   python3 ~/.hwf/scripts/stop-test-services.py <本 issue worktree> --port <本轮用过的端口>
   ```

   脚本按「cwd 在 worktree 内且在监听端口」认领整棵服务进程树（含 `pnpm exec` 包装进程），不碰 Agent 和其他 worktree。只关 pane 或按 Ctrl-C 不够；omp 命名服务另用 `write proc://<名称>/kill` 清掉记录。部署后验收不启动本地服务，只清理本机浏览器、测试客户端和辅助进程，不关闭远端服务。
2. 确认本轮所有 `test-record.py start` 都已执行 `stop` 收尾，结束自己创建的浏览器会话或本轮启动的 Electron 客户端窗口，记录清理结果；不关用户窗口，不清共用资料。
3. 若本轮创建了 `<证据目录>/browser-profile`，删除它并在报告里确认；不上传含登录凭据的目录。
4. 只关本 issue 的进程，不关别人的服务。

### 7. 补经验

收尾前把已确认有效的登录方式、入口、造数方式（含可复用 ID）、坑与解法补进 `howto.md`，失效的直接改，不写流水账。可长期复用的数据补进 `test-data.md`：按环境、账号写类型、ID、查找方式、自检办法、来源任务、最后确认日期。造数前先查清单并自检，能复用就复用。不记密码和 token，不破坏或删除清单里的数据，必须改动就测完恢复。

## 报告内容

预检结论与耗时；命令、环境、被测版本（HEAD 或部署 SHA、客户端版本）；验收条目逐条的结果、已上传录屏的 `markdown`/`web_url` 与时间段（及必要的补充截图链接与补图原因）；日志与报告路径；启动和关闭动作、端口回读结果、残留进程；录屏收尾、浏览器关闭和 profile 删除确认。全部通过才写通过。
