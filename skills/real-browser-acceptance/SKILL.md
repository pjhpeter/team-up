# 真实浏览器验收

用真实浏览器（或 Electron 桌面窗口）、真实后端，按用户能做的操作逐条走验收点，优先保存本轮实际操作的过程录屏（无法录屏或静态细节看不清时用截图补足）并给出结论；测完把自己启动的服务、浏览器会话和桌面客户端关干净。看起来对、单元测试过了、jsdom 跑通了，都不能代替这一步。

先确定这一轮是哪种：

- **本地验收**（仅涉及桌面原生能力、会污染测试环境公共库或无可用测试环境等客观条件时）：在本 issue 的 worktree 新启动专属服务来测。
- **部署后验收**（直上测试环境合并冒烟、测试环境冒烟、debug 模式）：直接测已部署的测试环境地址，**不启动**本地 Web 服务或开发版 Electron，也不关闭远端服务。涉及主进程、preload、安装更新等桌面原生能力时，用包含本次改动、连接测试环境的测试客户端，记录测试包版本、构建 SHA、来源和连接环境。网页通过不能代替桌面原生验收。

## 步骤

### 1. 读已有经验与固定证据目录

- 开测前读本任务的 `<任务目录>/test/howto.md`（登录、入口、造数、坑），以及项目的 `<主仓库>/.hwf/test-data.md`（可复用测试数据；主仓库是 `git rev-parse --git-common-dir` 的上一级）。文件不存在就在收尾时新建。
- **证据目录固定前缀与大包禁令**：本轮全部本地录屏、截图、报告和终端日志，在团队流程中一律写入 `<主仓库>/.hwf/tmp/<任务标识>/testing/<轮次>/`（绝对路径）；非团队单次测试写 `<仓库根目录>/.tmp/testing/<轮次>/`。派活若写了相对路径（如 `testing/xxx`），必须解析到 `<主仓库>/.hwf/tmp/<任务标识>/testing/xxx`，**严禁**在仓库根目录或 worktree 根目录直接新建 `testing/`、`evidence/`、`test/` 等顶层目录，也严禁修改仓库 `.gitignore` 遮盖放错位置的测试产物。证据目录只保留文本报告、JSON/哈希摘要、截图与压缩 `.mp4` 录屏；需要拆检 `app.asar`、`.dmg`、`.pkg`、`.app` 或流水线大归档包时，一律解压到 `/tmp/hwf-inspect-<编号>/`，提取摘要后在本轮清理步骤立即删除 `/tmp/hwf-inspect-<编号>/`。

### 2. 启动专属服务（仅本地验收）

- 以本 issue 的 worktree 为 cwd 新启动服务，不复用本 worktree 先前 issue、其他成员、用户或任何已在运行的服务。
- 先查端口归属，被别人占用就按仓库规则另选空闲端口（若仓库开发版 Electron 或本地网关要求固定端口如 `3001`，核实该端口空闲后直接启动，被他人占用时才报阻塞，不复用、不停止对方服务）。记录端口、origin、进程标识、启动时间。无法保证 origin 隔离就报阻塞。
- 确需在别处启动，记录 PID，收尾按 PID 关闭。
- 只有涉及主进程、preload、安装更新、其他原生能力或需求明确要求时才启动 Electron；需要本地 Electron 验收时直接在本 issue worktree 运行仓库开发版 Electron 启动命令并用 `Computer Use` 操作该独立窗口，除非需求本身验收安装包/自动更新，否则不索要签名安装包，也不为启动本地服务请示用户。网页和 Electron 都涉及时分别覆盖、分别列结果。

部署后验收改为：核对测试环境实际部署的版本包含本次代码（MR、源 SHA、部署 SHA、成功的部署作业）；前后端都改时分别核对。只凭「已合并」不能开测。

### 3. 预检（不超过 10 分钟）

报告开头逐项写结论和耗时：

1. 被测版本与派活一致：本地验收核对 HEAD 和专属服务；部署后验收核对部署或客户端版本。读取 `docs/agents/herdr-project.yaml` 的 `smoke`：默认只测 `default` 不为 `false` 的站点（如国内测试站）；`default: false` 的站点（如国际/海外站）仅在用户明确要求或本次改动专门涉及该站点独有配置/分支逻辑时才测，未触发时**不检查该站点账号席位、不因缺该站点账号报阻塞**，报告注明「<名称>未验（默认不验）」。
2. 按当前全局「浏览器与 Electron 测试铁律」（`~/.agents/rules/topics/04-tool-usage.md`）按被测对象（网页浏览器或 Electron 桌面窗口）选择对应工具。使用本轮独立的测试环境与分配的账号打开被测页面或独立客户端窗口，确认能实际操作，且能通过 `~/.hwf/scripts/test-record.py` 录制过程视频并解码回放。
3. 页面正常渲染；账号能登录，权限和积分够；真实用户操作能走到功能入口；依赖接口已部署，没有未部署或鉴权错误。
4. 逐条列出每个验收点需要的前置状态和造法。

**自己解决的问题**：浏览器空间、登录、遮罩和弹窗、端口占用、找页面入口、造测试数据。先查 howto 里的已知做法，再换办法；同一问题最多换 2 种办法，仍失败才标阻塞，并报告每种办法和现场。

- **本机测试账号自动登录与脱敏入口**：按派活分配的测试账号，可直接通过 `HWF_TEST_ACCOUNT=<账号> python3 ~/.hwf/scripts/test-browser.py <worktree> --url <被测地址> --mode ego --space-name <空间名> [--clear-origin] --out <本轮证据目录>` 自动从环境变量、本机凭据文件（`~/.agents/secrets/look-ai-test-accounts.md`）或 macOS 钥匙串（`hwf-test-account`）读取密码完成脱敏登录（输出仅含掩码账号，命令行参数不暴露明文账号密码；Electron 独立客户端窗口用 `Computer Use`）。涉及套餐或计费状态（如免费号、试用期、已付费）时，通过 `test-account.py pool` / `claim --require-tag` / `tag` 核对并记录套餐标签。录屏在登录进入目标界面后再开启（验收登录页本身时只录登录窗口，绝不打开或录制凭据文件，报告和日志不打印明文密码）。测试专用账号在自动化验收中输入密码属于正常自理操作：**严禁**未经自动登录尝试就直接停在登录页叫用户手动登录，也**严禁**在测试后以“自动化输入过密码”为由要求用户轮换测试账号密码；仅当无可用测试账号、触发无法自助收码的真人专属验证/硬件鉴权，或自动登录排障后仍失败时，才报「登录窗口已就绪」交用户接手。
- **Ego Lite 复用默认实例与测试站点单站清理（换号 / 未登录通用）**：一律通过默认 `ego-browser` CLI 复用当前运行的默认 ego lite，并在其中新建本轮 `TaskSpace`；按全局规则 `~/.agents/rules/topics/04-tool-usage.md`，**严禁**手动启动、多开、重启或关闭 `ego lite.app` 进程（禁止 `open -n`/`open -a`、`Contents/MacOS/ego lite`、`--user-data-dir`、`--ego-server-name`、`--startup-ego-browser-service`，以及打开 `chrome://profile-picker/` 新建个人资料），也不向用户索要空白浏览器资料或 `profileId`。打开非生产测试站点（本地专属端口或 `smoke` 测试域名，如 `develop.bootingai.net`、`app.develop.lookai.app`）时，若自动带入已有登录态，而本轮需要切换分配账号或验收未登录/匿名状态，按两步自行清理：
  1. **核对同站点并发**：本地专属端口按 `origin` 天然隔离可直接清理；共享测试域名先查 `listTaskSpaces()` 中其他活跃空间的标签页 URL（团队任务同时查 `python3 ~/.hwf/scripts/test-account.py list` 是否有其他在途任务正持有同站点账号），确认没有其他任务正在使用同一测试域名。若同一测试域名正被其他在途任务使用，报并发占用等待，不清对方会话。
  2. **仅清当前测试站点登录态**：在该测试页执行 `localStorage.clear(); sessionStorage.clear()`，调用 `Storage.clearDataForOrigin`（`origin` 仅传当前测试站，`storageTypes: "cookies,local_storage"`），并用 `Network.getAllCookies` 过滤出 `domain`（去前导点后）等于当前测试站 hostname 或其专属测试子域（如 `develop.bootingai.net`、`app.develop.lookai.app`、`develop.lookai.app`）的 Cookie 逐条 `Network.deleteCookies`，刷新后即处于未登录态，按本轮需要保持匿名验收或登录本轮账号。**严禁**调用 `Network.clearBrowserCookies`、`Network.clearBrowserCache` 或无 `browserContextId` 的 `Storage.clearCookies`，严禁删除一级根域、生产域名（如 `look-ai.cn`、`lookfashion.ai`）或其他子域（如 `git.bootingai.net`、`admin.lookai.cc`）的 Cookie。

**直接停下回报的问题**：代码缺陷；账号、积分、权限不足；后端未部署或接口报未部署；测试工具本身不可用。**例外（外部沙盒固有受限）**：若延伸任务继承了关联前置单已证实的第三方沙盒限制，或预检/首轮实测确认某分支因外部沙盒固有机制（如一次性测试卡、绑卡阶段风控拦截、三方验证码/额度限流等）无法重复触发，按 `~/.hwf/protocol/review-testing.md` §8 自动切入降级闭环（真实接口契约核对 + 定向单测模拟响应 + 报告如实披露未覆盖生产分支；涉及前端界面交互时挂载同版本已审组件夹具补录 `.mp4` 并注明模拟边界），不得发 `todo` 向用户重复索要新沙盒窗口或真卡。

预检第 1–3 项处理后仍不成立，或所有验收点都造不出条件：不跑验收点，按第 6 步清理，以「阻塞」结尾，附对应预检项、报错原文、现场录屏或截图、已试过的办法。只有部分验收点造不出条件，就逐点标阻塞，其余继续；正式测试中某点造条件连续失败 2 次，同样跳到下一点。预检失败不等于免测，真实运行取证门禁仍未满足。

### 4. 逐点验收与过程录屏

- 按已评审的用例（无用例 snippet 的 debug/极简模式按 issue 或 §0 验收点）执行，不按实现结果临时降低通过标准。
- 用真实用户导航到达功能，真实请求连接真实后端，不用模拟接口；后端改动按接口验收，存在页面操作链路时一并覆盖。遵守仓库 `AGENTS.md` 的环境、端口、登录、取证要求，不抢同一个登录会话。
- **按验收标准编号成段保存过程录屏（`.mp4`）**：按已确认验收标准编号组织录制与文件命名（如 `ac1-<场景>.mp4`、`ac2-<场景>.mp4`；同一连贯操作流顺手覆盖相邻多条标准时命名为 `ac1-ac3-<场景>.mp4`，单段控制在 3 分钟、20 MB 以内）。每段必须完整覆盖对应验收条目的「**操作前状态 → 关键操作 → 可观测结果**」，把同一条冒烟或连续页面切换录在一段完整视频内，不按每次点击切成几秒一段的零碎片段；失败或受阻也保留现场。统一使用 `~/.hwf/scripts/test-record.py`，禁止手写裸 `.mov` 录屏脚本，只录本轮被测页面或独立客户端窗口，不录桌面、其他窗口或输入密码/令牌的过程：
  - **网页（`ego-browser`）**：
    ```bash
    python3 ~/.hwf/scripts/test-record.py start --mode ego --space-id <spaceId> --out <证据目录>/ac1-<场景>.mp4
    # 照常执行 ego-browser nodejs 页面操作与断言（走官方截图采样，不使 @ref 引用失效；handOff 人工接管期间自动暂停抓帧）
    python3 ~/.hwf/scripts/test-record.py stop --out <证据目录>/ac1-<场景>.mp4
    ```
  - **Electron 桌面窗口**：在完成登录进入被测界面后开录（除非验收点本身测未登录界面）：
    ```bash
    python3 ~/.hwf/scripts/test-record.py windows --pid <客户端或启动进程PID>
    python3 ~/.hwf/scripts/test-record.py start --mode window --pid <PID> [--window-id <WID>] --out <证据目录>/ac1-<场景>.mp4
    # 照常用 Computer Use 操作该独立客户端窗口完成验收
    python3 ~/.hwf/scripts/test-record.py stop --out <证据目录>/ac1-<场景>.mp4
    ```
  `stop` 自动校验视频可解码回放、时长与尺寸；逐条记录每个验收标准在对应录屏中的起止时间段（如 `00:04–00:18`）和「通过 / 失败 / 阻塞」结论。
- **已录 `.mp4` 必交与截图补足边界**：凡已录制有效 `.mp4` 的验收点，必须上传并在报告中交付该视频，**严禁弃用已录视频退回只交静态截图**。录屏已清楚覆盖的验证点无需重复逐点截图；仅当客观无法录屏、录屏不可回放、小字号文案或像素间距在视频中看不清（均须说明具体原因），或任务明确要求截图时，用同轮关键步骤与结果的截图补足。
- **界面或文案回改后必须重录**：凡测试回改或用户中途要求修改了界面布局、按钮位置、样式或可见文案，受影响验收条目的改前录屏仅作历史记录保留，**不得充当通过证据**；必须基于改后代码重新录制最新交互画面（只补改后静态截图不能替代改后录屏；若涉及一次性绑卡/扣款等外部副作用无法在测试环境重跑全链路，在真实浏览器挂载同版本已审真实组件夹具补录完整交互过程并如实注明模拟边界）。
- **按改动大小定走查深度**：
  - **纯局部显隐、文案或单行样式微调**（未改动滚动容器、响应式断点规则、接口契约或按钮确认链路）：在默认桌面视口（≥1200px）打开真实目标页面/弹窗，确认目标内容已按要求显示或隐藏、无异常空行/错位、相邻操作按钮正常展示即可（通常 1 段短录屏，静态文案细节可附 1 张截图）；**不额外注入大批量虚构数据（如 20 条假列表）跑多视口滚动矩阵，也不逐个重测未改动的确认弹窗或退出链路**。
  - **新增页面/弹窗、修改滚动容器或响应式布局、改动交互请求链路**：有设计稿核对颜色、字体、字号、间距、圆角、层级、文案（宽高依内容和容器判断，不照抄固定数值）；无设计稿核对对齐、间距、换行、溢出，无重叠、错位、截断、异常空白，并按受影响范围验证对应视口、滚动与操作链路。偏差退回开发修复后复测。

### 5. 上传录屏与证据链接

用统一媒体上传脚本把本轮交付的 `.mp4` 录屏（及必要的补充截图）上传为 GitLab 项目附件，脚本自动回读核验 SHA-256（拒绝裸 `.mov`）：

```bash
python3 ~/.hwf/scripts/upload-media.py create --repo <主仓库路径> --file <证据目录>/ac1-<场景>.mp4 --alt "AC1 <场景说明>"
```

- **Herdr 团队任务**：`test` 只调用 `upload-media.py create` 静默上传附件换取链接，**不在 GitLab issue/MR 发评论或改状态**；在测试报告中按已确认验收标准逐行输出「验收标准逐条对账表」（`| 验收项 | 结果 | 录屏与时间段（或免录说明） |`），每条写明「通过 / 失败 / 阻塞」、脚本原样返回的 `markdown`（`![说明](/uploads/...)`，供 GitLab 评论直接渲染原生 `<video>`/`<img>` 播放器）、对应起止时间段（如 `00:04–00:18`）及 `web_url`（`https://<host>/-/project/<数字项目ID>/uploads/...` 完整直链，供飞书端点击打开；**严禁手拼 `/<组>/<项目>/uploads/...` 旧路径，新版 GitLab 会 404**），供调度者逐项 `check` 后原样放进完成评论折叠区外。
- **单次非团队任务**：直接对外回报时，GitLab 评论同样在折叠区外附上「验收标准逐条对账表」，单元格内原样内嵌 `markdown`（不能放进反引号或代码块）、起止时间段与 `upload-media.py` 输出的 `web_url` 裸链接，标注环境与 SHA，回读确认链接可访问。
- 保留旧轮次的失败录屏/截图和记录，不覆盖、不改绿；本地路径或只附本地报告不算交付，无访问或上传能力即报阻塞。

### 6. 每轮清理（回报前必做）

1. 关闭本轮启动的服务和全部后台进程，退出码 0 才算完成，输出原文贴进报告：

   ```bash
   python3 ~/.hwf/scripts/stop-test-services.py <本 issue worktree> --port <本轮用过的端口>
   ```

   脚本按「cwd 在 worktree 内且在监听端口」认领整棵服务进程树（含 `pnpm exec` 包装进程），不碰 Agent 和其他 worktree。只关 pane 或按 Ctrl-C 不够；omp 命名服务另用 `write proc://<名称>/kill` 清掉记录。部署后验收不启动本地服务，只清理本机浏览器、测试客户端和辅助进程，不关闭远端服务。
2. 确认本轮所有 `test-record.py start` 都已执行 `stop` 收尾，结束自己创建的 `TaskSpace`（`task.finish`）或本轮启动的 Electron 客户端窗口，记录清理结果；**不关用户窗口，不重启或关闭 `ego lite.app` 主进程，不清共用资料**。
