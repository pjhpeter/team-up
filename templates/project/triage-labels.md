# Triage Labels

本仓库的标签只有 9 个，分三组。含义、什么时候换、每张 open 的 issue 恰好一个 `状态:` 标签等规则，以 `~/.hwf/protocol/planning.md`「issue 数量与进度标签」为准。不得新增标签。

| 组 | 标签 | 含义 |
| --- | --- | --- |
| 类型 | `需求` | 根 issue：一个需求最上层的 issue（含 spec） |
| 类型 | `子任务` | 根 issue 下确实要并行开发的子 issue |
| 进度 | `状态:等你处理` | 需要人拍板、执行、澄清或决定做不做 |
| 进度 | `状态:待开始` | 已排好，等人开工 |
| 进度 | `状态:方案中` | 写方案、方案/用例评审 |
| 进度 | `状态:开发中` | 开发与代码评审 |
| 进度 | `状态:测试中` | 自动化测试、合入测试分支、冒烟 |
| 进度 | `状态:待上线` | 代码已在 release 分支，等合上线分支 |
| 开关 | `herdr-auto` | 收件箱开关：带它的 issue 指派给 agent 账号时自动启动 Herdr 交付 |

走 Herdr 交付的 issue，建单时只打 `herdr-auto` 并指派，`需求` 与 `状态:` 由调度者按阶段自动维护，不要手动选。

## Skill 角色对照

skill 里写的五个分诊角色，在本仓库按下表落到实际标签：

| Canonical role    | 本仓库做法 |
| ----------------- | ---------- |
| `needs-triage`    | `状态:等你处理` |
| `needs-info`      | `状态:等你处理`，并在评论里写清要补充什么 |
| `ready-for-agent` | `状态:待开始` |
| `ready-for-human` | `状态:等你处理` |
| `wontfix`         | 不打标签：写一条评论说明不做的原因，然后关闭 |

skill 说要打「spec / type 标签」时，打 `需求`；实现子 issue 打 `子任务`，不打 `需求`。标签按精确名称匹配，缺失时不得自行创建别名，先报告（缺标签就重跑 `python3 ~/.hwf/scripts/init-project.py <仓库路径> --apply`）。
